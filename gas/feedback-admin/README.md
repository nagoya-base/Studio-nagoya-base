# 利用後アンケート管理画面（Issue #849 第2段階）

SNB・SNB mens・Studio X の利用後アンケート（#835）の回答を、**オーナー1人がスマホの管理画面だけで確認・対応**するためのGAS Web Appです。
日常の操作でGoogleスプレッドシートを開く必要はありません（Spreadsheetは保存先・非常時の確認用）。

全3段階：①フォーム・保存・通知 #835 → **②管理画面 #849（本書）** → ③予約連動・自動送信 #834。
**本番の自動メール配信は #834 完了までOFFのままです。**

## 構成

| 役割 | 場所 |
| --- | --- |
| 認証・閲覧API・対応更新API | `gas/feedback-admin/FeedbackAdmin.gs` |
| 画面（スマホ/PC） | `gas/feedback-admin/FeedbackAdminPage.html` |
| 集計・カード生成・更新入力の検証（純粋関数） | `scripts/feedback-analytics.js` |
| 回答Spreadsheetの識別・ヘッダ確認（#835と共通） | `gas/feedback/FeedbackRepository.gs` |
| 保持期間による月次削除（本番180日・テスト30日） | `gas/feedback-admin/FeedbackMaintenance.gs` |
| 配布物の組み立て | `scripts/prepare-feedback-admin-gas-project.js` |

公開Web App（`gas/feedback/`。回答受付・通知）とは**別のGASプロジェクト**です。管理者プロジェクトには回答受付（doPost）・通知・トークン処理を含めません。
既存 `/survey/`・`/mens/survey/` の管理画面（`gas/survey/admin/`）とも別物で、互いに影響しません。

## 画面

| タブ | 内容 |
| --- | --- |
| 概要 | 回答数・総合満足度の平均と分布・再利用意向・低評価（1〜2点）件数・未対応件数・通知失敗件数・対応状況の内訳 |
| 問題分析 | Q2/Q3の9項目ごとの「問題なかった／少し気になった／困った／該当なし／未回答」の件数と問題率（分母を表示。未回答・該当なしは分母から除外）、Q5の4カテゴリの件数 |
| ご意見・対応 | 未対応→対応中→その他の順、同じ状況なら新しい順のカード。ブランド・回答日時・総合評価・Q5・自由記述・通知失敗・対応状況。全設問は「全設問の回答を見る」で展開。カード内で対応状況とメモ（200字まで）を編集・保存 |

- 上部の絞り込み：ブランド（全体／SNB／SNB mens／Studio X）、期間（直近30日／90日／全期間）、「テスト回答だけを表示」。
- ご意見・対応の絞り込み：対応状況、問題・ご意見の有無（Q5で「特になし」以外を選択、または自由記述あり）。
- **テスト回答（`?test=1`）は既定ですべての集計・一覧から除外**します。「テスト回答だけを表示」をONにしたときだけ、テスト回答だけを表示します。
- 対応状況は **未対応／対応中／対応済み／対応不要**。#835 の初期値（問題・自由記述あり→未対応、それ以外→対応不要）と同じ列を使います。
- 保存ボタンは「保存中…」「保存しました。」「保存できませんでした…」を表示し、失敗時はもう一度押すと再試行します。
- 一覧は最大200件まで表示します（それ以上は絞り込んでください）。

## 安全のための仕組み

- デプロイは「アクセスしているユーザーとして実行／自分のみ」。さらに `FEEDBACK_ADMIN_EMAILS` に登録したアカウントだけを許可し、**API呼び出しごとに毎回確認**します。
  未設定・メールアドレスを取得できない・許可外のときは、画面も閲覧APIも更新APIも `FORBIDDEN` だけを返し、回答・自由記述を返しません。
- 更新APIは `response_id` とブランドで**1行だけ**を特定し、**`status` と `memo` の2列だけ**を書き換えます。
  該当なし（`NOT_FOUND`）・同じIDが複数（`DUPLICATE_RESPONSE_ID`）・ブランド不一致（`BRAND_MISMATCH`）・未知の項目（`UNKNOWN_FIELD`）は何も書きません。回答本文・ブランド・日時は変更できません。
- メモは制御文字を除き200字まで。先頭が `= + - @` のときは `'` を付けて保存します（数式として解釈させない）。
- 公開フロント（GitHub Pages）には新しい秘密情報もURLも追加していません。

## Script Properties（管理者プロジェクト。値はGitに書かない）

| キー | 内容 |
| --- | --- |
| `FEEDBACK_SPREADSHEET_ID` | #835 で作った利用後アンケート専用Spreadsheet のID（公開Web Appと同じ値） |
| `FEEDBACK_ADMIN_EMAILS` | 閲覧・更新を許可するGoogleアカウント（カンマ区切り）。未設定だと全員拒否 |

## 月次削除を管理者プロジェクトで行う理由

行を削除すると、それより下の行番号がずれます。対応更新（`updateFeedbackStatus`）は `response_id` で行を特定してから書き込むため、
削除が別プロジェクト（別ロック）で同時に走ると、ずれた後の行＝別の回答に書き込むおそれがあります。
そこで削除（`purgeExpiredFeedbackResponses`）を**同じ管理者プロジェクトに置き、同じ `LockService.getScriptLock()` で直列化**しています。
公開Web Appは末尾への追記だけを行い、既存行を動かしません（トリガー作成用の `script.scriptapp` 権限も公開側からは外しました）。

## 初期設定（オーナーの承認後に実施）

1. 配布物を組み立てる（`.gas-deploy/` は `.gitignore` 済み）：
   ```sh
   node scripts/prepare-feedback-admin-gas-project.js .gas-deploy/feedback-admin
   ```
2. **新しいGASプロジェクト**（公開Web Appとは別）を作り、`.gas-deploy/feedback-admin/` の全ファイル（`appsscript.json` を含む）を配置する。
3. スクリプト プロパティに `FEEDBACK_SPREADSHEET_ID` と `FEEDBACK_ADMIN_EMAILS` を登録する。
4. 「デプロイ → 新しいデプロイ → ウェブアプリ」：次のユーザーとして実行 **ウェブアプリケーションにアクセスしているユーザー**、アクセスできるユーザー **自分のみ**。
5. 発行された `/exec` URL をスマホのブラウザで開き、ホーム画面に追加（ブックマーク）する。URLはGitやIssueに書かない。
6. 管理者プロジェクトのエディタで `installFeedbackRetentionTrigger` を1回実行する（毎月1日4時台に保持期間切れの行を削除。初回は `script.scriptapp` の認可を許可）。止めるときは「トリガー」から `purgeExpiredFeedbackResponses` を削除する。

## 手動確認（公開前）

1. 自動テスト：`node --test test/feedback-*.test.js`
2. 許可外のGoogleアカウント（またはシークレットウィンドウ）で管理画面URLを開き、表示されないことを確認。
3. #835 のテストフォーム（`?test=1`）で数件回答し、管理画面で「テスト回答だけを表示」をONにすると表示され、OFFでは集計・一覧に出ないことを確認。
4. テスト回答のカードで対応状況とメモを保存し、Spreadsheetの該当行の `status` / `memo` だけが変わったことを確認。
5. スマホ幅で横スクロールが出ないこと、長い自由記述が折り返されることを確認。

## 困ったとき（Spreadsheetで確認する方法）

- 画面に「回答データを読み込めませんでした」と出る：`FEEDBACK_SPREADSHEET_ID` が正しいか、Spreadsheetの `settings` シートに `feedback_spreadsheet` の行があるか、`responses` の1行目（列名）が変わっていないかを確認。
- Spreadsheetの `responses` シートで、`brand` 列（snb / mens / studio-x）、`is_test` 列（1=テスト）、`status` / `memo` 列を見れば、画面と同じ内容を確認できます。
- 列名・列の順番は変えないでください（変えると保存・表示が止まります）。並べ替えやフィルタ表示は問題ありません。

## このPRに含めないこと

- 送信数・回答率、会員情報・予約者との突合、複数管理者ロール、監査DB、対応履歴の別テーブル、回答本文の編集。
- Booking連動・トークン接続・自動メール送信（#834）。本番デプロイ・配信設定の変更。
