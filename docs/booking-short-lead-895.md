# 直前予約（開始まで30分以下）の注意表示・確認チェック（Issue #895）

正本は Issue #895。旧方針「新規予約を開始60分前締切にする」は撤回済みで、本実装は**UIの注意表示と確認チェックだけ**。

## 仕様（実装済み）
- 予約フォームStep1で開始時刻を選んだ直後、**現在時刻から開始まで30分00秒以下**なら、開始時刻ボタンの直下に注意文と未チェックの確認欄を表示（SNB / mens / Studio X、日英共通の `_includes/booking_app_{ja,en}.html`）。30分超は非表示。冒頭には常時表示しない。
- 再評価のタイミング: 選択時／**次へ進む時**／**最終送信時**／約15秒ごと（開いたまま時間経過）。条件を満たして未チェックなら進行・送信せず、インラインエラー＋チェック欄へフォーカス（最終送信時はチェック欄のあるStep1へ戻す）。
- 開始時刻・日付・利用時間の変更、Step1へ戻る操作でチェックはリセット（古い同意は流用しない）。
- 判定は `BookingLogic.isShortLeadStart(date, 'HH:MM', nowMs)`（JST固定、境界は30:00を含み30:00.001を含まない）。

## 変更していないもの
- #885の30分前締切・2026-11-19施行ゲート、#758のルール、GAS、決済・通知、API。**同意はサーバーへ送らない**（受付の例外許可ではない）。
- 受付不可の候補はサーバーが返さないため、UIで復活しない。

## 端末時計のズレ
候補の有効性は従来どおりサーバーが正本。表示判定は端末時刻を使うが、availability応答の `Date` ヘッダーが取得できる環境ではその差分で補正する（取得できなければ端末時刻のまま。APIは変更しない）。
