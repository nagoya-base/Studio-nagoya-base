# SNBC売上・現地払い受領の記録（Issue #995 PR-C）

オーナー1人用の運営アプリ（Ops）で、SNBCイベントの実収入と現地払いの受領確認を記録し、年商（80万／130万円）・月次KPIへ反映する。
金額・氏名などの実データはこのリポジトリに書かない。

## オーナーの手動準備（デプロイ前に1回）
1. 既存の**メモ用スプレッドシート**（Script Property `OPS_TASKS_SPREADSHEET_ID` が指すファイル。新しいファイル・Script Propertyは不要）に、次の2タブを作る。
   1行目にヘッダーを**この順・この綴り**で置く（アプリはタブもヘッダーも作らない）。
   - `SNBCEvents`: `eventId, eventDate, title, paidCount, receivedJpy, refundedJpy, directCostJpy, updatedAt, revision`
   - `OnsiteReceipts`: `bookingId, receivedJpy, refundedJpy, method, receivedOn, updatedAt, revision`
2. 実行アカウントがそのファイルの編集者であること（既存メモ機能と同じ）。予約台帳とは別ファイルであること（同じIDなら停止する）。

## 使い方
- ホーム → 年商カード → **「SNBC売上を記録」**: 開催後に1イベント1回（開催日・イベント名・実受領総額・返金済総額、任意で有料人数・直接経費）。登録済みは一覧から訂正・削除。
- 予約詳細（現地払いの予約のみ）→ **「現地払いの受領を記録」**: 受け取った**累計**・返金済**累計**・方法・受領確認日。予定料金は参考値で、自動確定しない。

## 集計ルール（要点）
- SNBC: 開催済み `受領−返金` を開催月（JST）に1回。経費は年商から引かない。行が無ければ「未入力・要確認」。
- 現地払い: 台帳（`paid`／`feePaidAmount`）に受領記録がある予約は台帳を優先し、手入力は加算しない（両方あれば「受領記録重複」で要確認）。
  台帳に記録が無い現地払いだけ、手入力の `受領−返金` を利用終了後に計上。取消済みは、取消確定日時より後に更新した記録だけを取消確定月の残額にする。
- テスト予約・アタルは従来どおり売上から除外（一覧には残る）。
- 保存先未設定／タブ欠落／ヘッダー不一致／重複ID／読取失敗は0円とせず「部分計・警告」。旧イベント・旧現地払いは手入力で補完するまで全体年商とは断定しない。

## 安全性
- 書込み先は上記2タブの固定範囲のみ（予約台帳・`Tasks` タブへは書かない）。ID・タブ名・範囲は端末から受け取らない。毎回オーナー認可、`LockService`＋`revision`、`RAW` 書込み、書込み後の同一行再読込み。
- ログは固定コードと件数のみ（金額・予約ID・氏名を出さない）。保存列に個人名・連絡先・DM本文・Stripe IDは無い。既存の180日個人情報消去は変更しない。
