# 運営アプリ「未対応メモと期限管理」（Issue #941 / 親 #935）設計・運用メモ

**正本は Issue #941（本文＋タケルの実装指示コメント）。** 本書は実装の説明と運用手順です。
**マージ・デプロイ・初回の権限承認・実利用確認は、いずれもこのPRでは未実施です**（§9）。実在の予約・個人情報・ID・秘密値は記載していません。

## 1. 何を追加したか

#936 の運営アプリ（所有者だけが開く専用GASの画面）に、同じURL・同じ認証のまま **「メモ・期限」タブ**を追加した。

| 項目 | 内容 |
| --- | --- |
| メモの項目 | 件名（必須・80字）、任意の予約ID/サービス、状態（未対応/対応中/完了）、短いメモ（500字）、任意の期限、証跡リンク（https のみ・300字）、更新日時 |
| DMの扱い | 件名とリンクを**手入力で登録**するだけ。DM全文の保存・自動取得・送信はしない。予約に結び付かない問い合わせも登録できる |
| 一覧 | 上部に「未完了◯件・期限超過◯件」。並びは **期限超過 → 未完了（期限が近い順・期限なしは後ろ）→ 完了**。完了は通常一覧から外れ、「完了を表示」で再確認できる |
| 期限超過 | 未完了で、期限日（JST）が今日より前。期限の**当日は超過にしない**。完了は期限が過ぎても超過にしない |
| 自動判断 | しない（優先度計算・自動分類・自動期限設定は無い） |

対象外（作っていない）: SNS告知カレンダー、DM自動連携・自動返信、変更前後の履歴/監査表、汎用データ基盤、専用バックアップ/CSV復元機能。

## 2. 保存先（予約台帳とは別）

- **所有者が手動で用意した、予約台帳とは別の専用Googleスプレッドシート1つ**。中の **`Tasks` タブだけ**を読み書きする。このアプリはファイルを**作成しない**（自動作成は廃止。#957 のアプリ作成方式は実環境で `drive.file` が手動作成ファイルに届かず保存できなかったため）。
- 保存先の指定: サーバー側 Script Property **`OPS_TASKS_SPREADSHEET_ID`**（URLではなくIDのみ）。画面・クライアントは保存先ID/範囲を指定できない。未設定の間は一覧は「保存先が未設定」と表示し、保存は `STORE_FAILED`（`reason=NOT_CONFIGURED`）で止まる。**別ファイルを勝手に作らない**。
- 列（固定・11列、`Tasks` タブの1行目）: `taskId, title, bookingId, service, status, memo, dueDate, evidenceUrl, createdAt, updatedAt, revision`。氏名・メール・電話・DM本文・履歴の列は持たない。
- 書込みは `valueInputOption=RAW`（`=` や `+` で始まる入力を**式として評価させない**）。件数上限は1000件（超えたら `TOO_MANY` で止める）。範囲は `Tasks!A:K` に固定。
- **Tasksタブがない／1行目が空・不一致の場合は、何も書かず・初期化もせず停止**（`STORE_FAILED`・`reason=SCHEMA` または `READ_HTTP/400`）。他のタブ・他のデータには触れない（読みも書きもしない）。初期化は §8 の手順で所有者が手動で行う。既存の `Tasks` が正しいヘッダーを持つ場合は、再作成・消去をしない。

### 権限（scope）の変更と、なぜ `spreadsheets` か

**調査結果**: `drive.file` は「このアプリが作成した、またはユーザーがこのアプリで開いた（Picker等）ファイル」にだけ届く。ID を設定しただけの手動作成ファイルには**アクセス保証がない**。Sheets API でファイル単位に絞れる最小のscopeは無く、既存ファイルを読み書きできる最小は `spreadsheets`（全スプレッドシート）。Picker方式は別のGCPAPIキー・プロジェクト設定・画面実装が要り、今回の規模に合わないため採らなかった。

| scope | 変更 | 理由・届く範囲 |
| --- | --- | --- |
| `spreadsheets` | **追加** | 手動用意の保存先の読み書き用。**ファイル単位では絞れず、技術上は予約台帳にも届く**。そのため権限ではなく下記「コード側の固定」で書込み先を限定する |
| `spreadsheets.readonly` | **削除** | `spreadsheets` に包含されるため不要（二重に持たない） |
| `drive.file` | **削除** | 保存先を作成しなくなったため不要 |
| `script.external_request` / `userinfo.email` | 維持 | 外部通信・所有者認可 |
| `drive`（全体）・メール・カレンダー・トリガー | **追加しない** | デプロイ検査が拒否する |

**重要: これはOAuthレベルの読み取り専用ではありません。** 台帳は「コード上GETのみ・書込み先は別IDのTasks表だけ」という**コードとテストによる防御**で守っており、権限そのものは台帳にも書ける範囲です。再承認画面にも「表示・編集」と出ます。

検査を外したのではなく、**承認リスト（`APPROVED_SCOPES`）を正確に2件ぶん更新**し、manifest と過不足なく一致することをテストで固定している。**所有者の再承認が必要**（§8）。

コード側の固定（テストで検査）:

- 書込み先は **Script Property `OPS_TASKS_SPREADSHEET_ID` のIDだけ**。ブラウザーから保存先ID・範囲・シート名・版番号を受け取らない（許可項目以外のキーは `INVALID_PARAMS` で拒否）。
- 保存先IDが予約台帳ID（`OPS_SPREADSHEET_ID`）と同じ、またはID形式が不正なら、**読み書きせず停止**（`TARGET_IS_LEDGER` / `TARGET_INVALID`）。
- メモの処理（`OpsTasks.gs` / `OpsTasksStore.gs`）は予約台帳の読み取り経路（`OpsSource.gs`）を呼ばない。予約台帳の読み取り（`OpsSource.gs`）は従来どおり **GETのみ**。
- 予約の同期でメモを上書きしない: そもそも同期処理が無い。予約との結び付きは手入力の予約ID/サービス名の文字列だけで、予約一覧の取得はメモ側へ一切書かない。
- アプリは Script Properties を**書き込まない**（読み取りのみ）。`LockService` は `OpsApi.gs` のメモ用アダプターだけ。
- 予約台帳の読み取り（`OpsSource.gs`）は GET のみで、書込み・作成系のコードを持たない（静的テストで検査）。

## 3. 認可・検証（サーバー側が毎回）

- すべての操作（一覧・保存・削除）が `OpsApi.handle` の所有者認可（#936と同じ）を通る。未認証は `UNAUTHENTICATED`、所有者以外は `FORBIDDEN`、**拒否時は保存先へ通信すらしない**。
- 検証（画面の検証は補助。正本はサーバー）: 件名必須・80字、メモ500字、予約ID（英数字と `- _ : .`・64字）、サービスは既知の区分のみ、状態は3値のみ、期限は実在する日付、リンクは `https://` のみ（空白・`<>"'\@`・認証情報つきを拒否）、制御文字を拒否。
- エラー応答は固定コード＋固定文のみ。Googleのエラー本文・ID・トークンは返さず、ログにも出さない（固定の理由語のみ）。

## 4. 接続契約（画面⇔バックエンド）

```
list:    opsListTasks()                                → { ok, storeReady, items[], counts{open,overdue,done,stale}, todayJst, retentionDays, purge{deleted,failed}, skippedRows }
save:    opsSaveTask({ input, expectedRevision|null }) → { ok, task, replayed?, unchanged? } | { ok:false, error }
remove:  opsDeleteTask({ taskId, expectedRevision })   → { ok, deleted, alreadyDeleted? } | { ok:false, error }
error.code（追加分）: CONFLICT（error.current に最新） / STORE_FAILED（error.reason は固定語、error.hint は原因を断定しない固定の対応案） / BUSY / TOO_MANY
```

## 5. 保存の信頼性（失敗を成功に見せない）

| 事象 | 動作 |
| --- | --- |
| **保存中表示** | 画面は「保存中…」→ 成功時だけ「保存しました」。保存ボタンは保存中は無効 |
| **保存失敗** | 保存先がエラー・通信例外・応答不正 → `STORE_FAILED`（「保存できたか確認できていません」）。画面は「保存に失敗しました」を赤で表示し、**入力欄を閉じず内容を残す** |
| **書いたはずが無い** | 書込み後に保存先を**読み直して内容と版を照合**し、一致しなければ成功にしない（`reason=VERIFY`） |
| **二重送信（連打）** | 画面: 保存中は再送を受け付けない。サーバー: 新規は**端末が採番したID**を冪等キーにし、同じIDで同じ内容の再送は「保存済み」として成功（重複追加しない）、内容が違えば `CONFLICT`。失敗後の再送でも同じIDを使う |
| **同時更新（競合）** | 更新・削除は `expectedRevision`（読み込んだ版）が保存先と一致する時だけ実行。**不一致は上書きせず `CONFLICT`**。画面は最新の内容を示し一覧を取り直し、入力は残す。もう一度「保存」を押すと、最新の版に対する**明示的な上書き**になる（黙って消えない）。自分の更新が既に反映済みの再送（版が1つ進み内容が同じ）は成功扱い |
| **同時保存の衝突** | 書込みはスクリプトロック内（読み→書き→照合）。取れなければ `BUSY`（書かない）。ロック自体が使えない場合も失敗扱いで書かない |
| **保存先の異常** | ヘッダー不一致・taskId重複は **fail-closed**（一部だけ表示しない）。読み込めない行は件数（`skippedRows`）で返し、**画面が「◯行を読み込めませんでした。一覧・件数は不完全」と警告**する（全行が不正でも「未対応なし・正常取得」とは表示しない）。行の内容は応答・ログに出さない |
| **保存中の操作** | 保存中は入力欄・追加・編集・キャンセル・状態変更・削除・完了の表示切替を無効にし、届いた操作も無視する。遅れて返った成功応答は、**送信した下書きと同一で未変更の場合だけ**フォームを閉じる（別の下書き・変更後の入力は消さない）。古い一覧応答は破棄 |

履歴: `createdAt`/`updatedAt`/`revision` のみ。全項目の変更前後履歴・監査表は作らない。

## 6. 個人情報の最小化・保持（180日）・削除基準

方針の正本は `docs/privacy-retention-notice-690.md`（予約・会員等の台帳は起算日から180日で消去）。メモはそれと矛盾しないよう次のとおり。

- **書かない**: お客様の氏名・メール・電話・DM本文。画面に「件名とリンクだけ。氏名・連絡先・DM本文は書かない」と常時表示する。予約との結び付きは予約IDの文字列のみ（個人情報を引き写さない）。
- **自動削除**: 状態が「完了」のメモは、**最終更新日時から180日**を過ぎると、一覧の取得時にサーバーが保存先から**行ごと削除**する（トリガー不要・追加権限なし）。削除件数は画面に表示し、失敗した場合も画面に出す（次回取得で再試行）。完了後に編集すると起算が更新される。
- **未完了は自動削除しない**（「黙って消さない」ため）。180日以上更新が無い未完了は「更新なし・要見直し」と表示するだけ。見直したら完了にするか削除する。
- **所有者の削除**: 各メモの「削除」で即時に行を削除できる（確認ダイアログつき・版が古ければ競合）。**予約の削除・匿名化を行ったときは、その予約に結び付く手入力メモ（件名・メモ・リンク）も確認して削除する**。予約IDだけが残る場合も、不要なら削除する。
- 削除は保存先の行ごと（空欄化ではない）。削除後は保存先を読み直して不在を確認する。

## 7. 退避・復旧（短い手順。専用CSV復元機能は作らない）

- **保存先の確認**: GASの Script Properties の `OPS_TASKS_SPREADSHEET_ID` が、メモ専用ファイルのID。Googleドライブの「運営アプリ メモ（専用・予約台帳ではありません）」。
- **退避（任意）**: 重要な節目に、そのファイルを Googleドライブで「コピーを作成」するか、ファイル→ダウンロードでCSV/Excelを保存する。保存する場合も§6の保持期間を過ぎたら破棄する。
- **復旧**: 誤って削除/上書きした場合は、スプレッドシートの **バージョン履歴**（ファイル→バージョン履歴）で戻す。復元手順は Google標準のもののみで、アプリには復元機能を持たない。
- **ファイルを失った/IDを失った場合**: 新しい専用スプレッドシートを手動で用意し、§8 の手順で `Tasks` タブとヘッダーを作り、`OPS_TASKS_SPREADSHEET_ID` を差し替える（古いメモは引き継がれない。古いファイルが残っていれば手でコピー）。**誤ってIDを消さない**（消すと画面は「保存先が未設定」表示になり、保存できない）。
- **停止・撤去**: 専用ファイルをゴミ箱へ移せばメモは見えなくなる（画面は取得失敗を表示し、成功にしない）。

## 8. デプロイと初回の設定（短く）

1. **専用スプレッドシートの用意（所有者）**: 予約台帳とは**別の**Googleスプレッドシートを用意し、`Tasks` タブを作って A1:K1 に §2 の11列ヘッダーをこの順で入力（1行目固定は任意）。データ行は空のまま。他のタブがあっても触れない。**このファイルを、GASを実行するアカウント（デプロイ者）が編集できる状態にする。**
2. **保存先IDの設定**: GASエディタ→プロジェクトの設定→スクリプトプロパティに `OPS_TASKS_SPREADSHEET_ID`（IDのみ。URLは不可）を追加。**予約台帳のID（`OPS_SPREADSHEET_ID`）と同じにしない**（同じなら停止する）。IDは公開Issue・ログに書かない。
3. このPRをレビュー・**所有者が手動でマージ**した後、**Actions → Deploy ops reservations GAS → Run workflow**（main・入力なし）。既存のDeploymentを更新するのでURLは変わらない。デプロイ検査は新しい承認リスト（上表の3 scope）と過不足なく一致することを確認する。**PRブランチからのデプロイはしない**。
4. **所有者本人が利用URLを開き直し、Googleの承認画面で新しい権限（Googleスプレッドシートの表示・編集）を承認する。**（scopeが変わったため再承認が必要。承認前は台帳の取得・メモ保存が認可エラーで失敗表示になる場合がある。承認すれば予約の閲覧は従来どおり。）
5. 「メモ・期限」タブ → 「＋ メモを追加」で保存 → 再読込・別の端末で同じ内容を確認 → 確認用メモを削除。
6. 追加の Secrets・Environment は不要。既存の `OPS_OWNER_EMAIL` / `OPS_SPREADSHEET_ID` はそのまま。

保存に失敗した場合: 画面に「診断コード」と対応案（原因は断定しない）が出る。主な読み方: `NOT_CONFIGURED`=ID未設定 / `SCHEMA`=Tasksのヘッダー不一致・空 / `READ_HTTP/400`=Tasksタブなし等 / `…_HTTP/403`=権限未承認・ファイル未共有等 / `…_HTTP/404`=IDが違う。コードはIDや応答本文を含まない。

ロールバック: 同workflowの `rollback_version` で直前の版へ戻す。メモ専用ファイルは残る（戻した版はメモ機能を持たないだけ）。

## 10. 未完了・残リスク

- 上記「未実施／未確認」の項目。
- 前述のとおり、未完了メモは自動削除しない（見直し表示のみ）。予約の削除・匿名化に連動したメモの自動削除は**していない**（所有者が§6のとおり手で確認・削除）。自動化は予約台帳との結合になるため、今回の「予約台帳に触れない」方針を優先した。
- 同時に2端末で保存した場合の `BUSY` は、画面に表示するだけで自動再試行しない（入力は残るので、もう一度保存する）。
